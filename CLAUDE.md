# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An OpenGL 4.1 core-profile / C++11 demo scene for Linux (README marks it unmaintained): several OBJ models (house, tents, grass, farmer, goat, vulture, wood, sandworm, camel, rooster), a skybox, directional light with shadow mapping, fog, and a keyboard/mouse camera. There are no tests and no linter.

## Build and run

- Install `build-essential cmake libglfw3-dev libglew-dev libgl-dev`. GLM is vendored in `third_party/glm`.
- `cmake -S . -B build && cmake --build build` builds `build/opengl_scene`. `cmake --build build --target run` builds and runs it.
- Assets (`objects/`, `shaders/`, `textures/`) are loaded via paths relative to the working directory, so always run from the repo root. Filenames are case-sensitive (e.g. `objects/wood/wood.obj`).
- Tested with the Ubuntu 24.04 packages (CMake 3.28, GLFW 3.3, GLEW 2.2) on Mesa with a 4.6 core context.

- `tools/glb2obj.py` converts `.glb` models to OBJ/MTL for the loader (no dependencies). It bakes node transforms and extracts embedded base color textures. `--skip MESH_NAME` leaves out meshes, `--emissive` uses emissive textures instead, and `--no-textures` writes only solid colors. `tools/convert_models.sh` regenerates the sandworm, camel, rooster and black hole OBJs with the right options. Run it with `python3 -I`.

## Architecture

All code is in `src/`. `main.cpp` holds most of the application as globals and free functions: window/GL init, `initModels`/`initShaders`/`initUniforms`/`initFBOs`, `processMovement` (per-frame input handling), `renderScene`, and `main`.

Helper classes are in the `gps` namespace:
- `Shader`: compiles and links a shader program from vert/frag files.
- `Model3D` and `Mesh`: load OBJ plus MTL via `tiny_obj_loader.h` and draw with a given shader. Textures are loaded with `stb_image`. Each model lives in its own `objects/<name>/` folder, and the constructor takes the `.obj` path and the base dir for the `.mtl`.
- `Camera`: free-fly camera driven by `move()` and `mouse_callback()`.
- `SkyBox`: cubemap loaded from `textures/skybox/sahara_*.tga`, drawn with `skyboxShader`.

Rendering is two-pass shadow mapping. The depth pass uses `simpleDepthMap` and writes into `shadowMapFBO`/`depthMapTexture`. The main pass uses `shaderStart`, which does lighting, shadows and fog. The skybox is drawn after the opaque scene. Uniform locations are cached in globals (`modelLoc`, `lightDirLoc`, `fogLoc`, …) in `initUniforms`. A new uniform needs a global location, a lookup in `initUniforms`, and a use in the shader.

Vertex attribute locations are fixed (0 position, 1 normal, 2 texcoords) in `Mesh.cpp`/`SkyBox.cpp`, and each vertex shader declares matching `layout(location=N)`. All shaders start with `#version 410 core`.

`updateDayNight()` runs every frame. It advances `timeOfDay` (60 s per day) and computes `currentLightDir`, which is the sun, or the moon at night. That direction drives the shading and the shadow matrix. It also uploads the light color, ambient light, fog color and skybox tint. Don't set `lightDir`/`lightColor` uniforms elsewhere; they are overwritten each frame. `updateFireLight()` runs after the view matrix is set. It uploads the campfire as a flickering point light in eye space; the fire is at `FIRE_POS_MODEL` in the house model's space, so its transform must match the house's model matrix. The fire gets brighter as `nightFactor` rises, and B toggles it. Rain lowers `fireStrength`: the fire sputters, turns redder and goes out over about 10 s. It relights over 8 s once `rainAmount` reaches 0. `drawEmbers()` draws its visible flames and sparks: `gps::Embers`, additive `GL_POINTS` placed at `FIRE_POS_MODEL` (lowered to the logs) through the house's model matrix. Each particle's life cycle is computed in `embers.vert` from its seed and the time. The share of live particles follows `fireStrength`, and the wind carries the sparks, harder in a sandstorm or near the tornado. `drawBlackhole()` draws `objects/blackhole` before the moon, `BLACKHOLE_DISTANCE` from the camera along `BLACKHOLE_DIR`, It uses `moon.vert` with `blackhole.frag`. `tools/convert_models.sh` splits it into `blackhole_hole` (core and shells, `--no-textures`), drawn first in solid black, and `blackhole_disc` (the accretion ring, `--emissive`), added on top with additive blending. The hole hides the far side of the disc. Clouds and `overcast` hide it. It is not part of the shadow pass or collision, and the glTF animation is replaced by a slow spin. `drawMoon()` draws `objects/moon` after the skybox with its own unlit `moon` shader. It is placed `MOON_DISTANCE` from the camera along `moonSkyDir`, lit by `sunSkyDir` (which gives it phases), and faded with `nightFactor`. Moonlight is the night directional light: it is blue, strengthens as the moon rises, and drives `moonGlow`. `moonGlow` also tints the night ambient and draws a blue halo around the moon in `skyboxShader.frag`, which also thins the stars there. `MOON_ANGULAR_RADIUS` in that shader must match `MOON_SCALE`/`MOON_DISTANCE`. It is not part of the shadow pass or collision. Stars are procedural in `skyboxShader.frag`: hashed 3D grid cells on the direction vector, in two layers. They fade with `nightFactor` and turn with the sun/moon arc through `starRotation`, which `updateDayNight()` sets. Planets are steady points in the same shader. `Planets.hpp` computes their elongation from the sun and their magnitude from circular orbits with real radii, periods and J2000 longitudes. The calendar starts at `PLANET_START_DAY` plus `dayCount`, and P adds 10 days. `updatePlanets()` turns those into world directions and twilight/glare-faded brightness. It also adds the yearly star drift to `starRotation`. Clouds are one fbm noise sheet at `CLOUD_HEIGHT` in world space, in `shaders/clouds.glsl`. The skybox (drawing them, lit by `cloudLitColor`/`cloudShadowColor`), the moon (hidden behind them) and `shaderStart` (cloud shadows on direct light) all sample it, so the three agree. `Shader::readShaderFile` expands `#include "file"` lines, relative to the shader's folder, to share it. Each program that includes it needs `setCloudUniforms()`. Wind drift is `cloudOffset`, and [ / ] change `cloudCoverage`. Rain (R) eases `rainAmount` between 0 and 1. That forces overcast clouds, dims the sun or moon, greys the sky, hides the stars and planets, and makes surfaces wet with haze in `shaderStart` (`rainAmount` uniform). `drawRain()` draws `gps::Rain`, instanced `GL_LINES` whose positions are computed entirely in `rain.vert` (seed, time and a camera-centred wrap box), after everything else. Shooting stars (M) are `Meteor` structs that `spawnMeteor()` places near the camera's view. `updateMeteors()` uploads up to `MAX_METEORS`, which must match the skybox shader, as great-circle streaks for `meteor()` in `skyboxShader.frag`. They are drawn before the clouds, so clouds hide them. Lightning (`gps::Lightning`) strikes every 4-12 s while `rainAmount` > 0.8, or on Z. It builds a midpoint-displacement bolt with branches ahead of the camera and draws it as additive camera-facing ribbons after the moon. Its `Flash()` flicker is added to ambient, sky, cloud and rain colours in `updateDayNight()`. The rainbow is one bow in `skyboxShader.frag` around the point opposite the sun, drawn on top of the clouds. It is enlarged on purpose: `RAINBOW_RADIUS` is 48° (real ones are 42°) and `RAINBOW_WIDTH` is 4.5°. `rainbowStrength` stays up for `RAINBOW_HOLD_SECONDS` after R stops the rain, then fades over 20 s, and only while the sun is up and below the bow's radius. Puddles form only on the terrain: `puddleSurface` is 1 just while `grass` draws. They grow with `puddleWetness`, which fills over 15 s of rain and dries over 90 s. `applyPuddles()` in `shaderStart.frag` places them with fbm noise in model space on flat ground. Puddles form only on ground near `PUDDLE_PLANE_Y`, the flat camp floor. While puddles exist, `renderPuddleReflection()` first draws the models mirrored about that plane into `reflectionFBO`, clipped below it with `clipPlane`/`GL_CLIP_DISTANCE0`. That pass uses `drawSceneObjects(false)`, which leaves out the terrain, and the shared model-drawing code for both passes lives in `drawSceneObjects()`. The fire's eye-space position is re-uploaded for the mirrored view through `updateFirePosition()`, because `updateFireLight()` also advances the dousing and must run once per frame. `applyPuddles()` samples that texture at the pixel's screen position, offset by the raindrop ripples. Where the texture's alpha is 0, it shows a Fresnel reflection of the skybox cubemap (on `SKYBOX_TEXTURE_UNIT`), the cloud sheet and the moon. The skybox, moon, rain, lightning and fireflies are not drawn into the reflection pass. `uploadPuddleUniforms()` binds the reflection after it is drawn. Snow (V) eases `snowAmount` like rain, and R and V switch each other off. `overcast` is the largest of `rainAmount`, `snowAmount` and `sandAmount`. It drives the cloud cover and hides the stars, planets and fireflies. `drawSnow()` draws `gps::Snow`: `GL_POINTS` flakes that fall, flutter and wrap around the camera, all in `snow.vert`. `snowCover` builds up over `SNOW_COVER_SECONDS` while it snows. It melts over `SNOW_MELT_SECONDS` in full sun, barely at all at night, and within about 20 s in rain. In `shaderStart.frag` it turns upward-facing surfaces white in fbm patches that grow into a blanket, and hides the puddles. The aurora (`auroraStrength`) shows only when it is deep night, `snowCover` is nearly full and `overcast` is 0. `aurora()` in `skyboxShader.frag` draws two curtains toward -z, made of dithered horizontal layers 100-190 units up. It is drawn before the clouds and also adds a faint green ambient light. A sandstorm (U) eases `sandAmount` over `SAND_FADE_SECONDS`; U, R and V each switch the other two off. `overcast` includes `sandAmount`. `dustColor` follows the light, and the fog colour becomes it. `shaderStart` thickens the fog with fbm billows that move with `dustOffset`. `skyboxShader.frag` covers the sky in the same dust, solid at the horizon so the ground blends into it, and draws a pale sun disc. `drawSand()` reuses `gps::Rain` and `rain.vert` with an almost horizontal velocity for the blowing grains. The storm also speeds up the cloud drift, makes the fire flicker harder, dries puddles and hides the moon. The tornado (O, `gps::Tornado`) eases `tornadoAmount` over `TORNADO_FORM_SECONDS`. It counts towards `overcast`, and it darkens the light and tints the sky green-grey. The funnel is a grid mesh. Its bent axis and radius come from `shaders/tornado.glsl`, which `tornado.vert` and `tornadoDebris.vert` both include, so the debris circles the same axis. `drawTornado()` draws the funnel twice: the dense core (`shellScale` 1), then a torn outer shell (1.45). `extent` (touchdown from the clouds) and `tornadoWidth` (a thin rope while it forms or lifts) both follow `tornadoAmount`. `tornadoBase` wanders on a Lissajous path over the canyon floor. `tornadoShake` grows as it gets close to the camera: it shakes the view in `renderScene` and makes the fire flicker. `ambientNow`/`directNow`/`fogColorNow` keep the frame's lighting for effects drawn with their own shaders. Fireflies (`gps::Fireflies`, `FIREFLY_COUNT`) are additive `GL_POINTS` in a fixed world box around the camp. Their wandering and blinking are computed in `fireflies.vert` from a per-firefly seed and the time. `drawFireflies()` fades them in after dusk and hides them in rain. The skybox is drawn last, because `SkyBox::Draw` binds its own program.

Variable names don't match the models: `farmer` (`objects/farmer/farmer.obj`) is the drivable tank, and `tank` (`objects/goat1/goat1.obj`) is the rocket that C launches. The tank's transform is `tankModelMatrix()`, used by both render passes. `moveTankWithCollision()` applies the arrow-key movement and undoes it, or slides along one axis, if the tank's XZ footprint would newly overlap a static object. Footprints are oriented boxes built from per-mesh bounds (`Model3D::GetMeshBounds`, `Collision.hpp`). The obstacles are the house, tents, wood pile, the camel (`camelBounds` through `camelModelMatrix()`) and the rocket while it is on the pad. The terrain (`grass`), the bird and the sandworm are excluded. The sandworm (`objects/sandworm`) keeps its Sketchfab coordinates in the OBJ. `sandwormModelMatrix()` re-centres it on `SANDWORM_MODEL_BASE` and places it 1.5x size in the valley about 58 units toward -z. It sits low enough that the model's own flat sand plate stays under the terrain, and it is drawn in both passes. The rooster (`objects/rooster`) wanders the camp: `updateRooster()` runs each frame after `updateDayNight()`. It picks random targets with a clear straight path inside `ROOSTER_AREA_MIN`/`MAX`, turns, walks with a hop and waddle, stops to peck, runs from the tank when it is within 3.5 units and sleeps at night. `roosterPos`/`roosterHeading` are in camp space, before the Q/E rotation. Its collision check is a fixed square against `sceneObstacles()` plus the tank, and it is not an obstacle for the tank. Movement uses `frameDt`, which is computed once per frame at the top of `renderScene`.

Input uses a `pressedKeys[1024]` array set by the GLFW key callback and read each frame in `processMovement`. Keys: WASD plus mouse move the camera; Q/E rotate the scene; K/L rotate the sun/moon arc; N pauses the day/night cycle; T skips ahead; P skips 10 days; [ / ] change cloud cover; R toggles rain; V toggles snow; U toggles a sandstorm; O toggles a tornado; Z strikes lightning; M spawns a shooting star; B toggles the campfire; F/G fog on/off; H/J lights on/off; X toggles wireframe; arrow keys drive the tank; C launches the "rocket"; Esc quits. Note that X toggles on every frame while held.
